# Module reference

This guide maps maintained source under `src`. The generated Prisma client in `src/generated/prisma` is intentionally omitted; edit the schema and regenerate the client instead. For system flow and domain concepts, see [Architecture](architecture.md).

## App Router: `src/app`

Pages assemble server-rendered views and read data; route-local `"use server"` modules adapt form input to domain operations. Client components provide browser interaction and call those actions or HTTP endpoints.

| Route area | Responsibility and key files |
| --- | --- |
| `/` and shared shell | [Home](../src/app/page.tsx) branches between the public landing page and signed-in experience. [Root layout](../src/app/layout.tsx), [global CSS](../src/app/globals.css), [theme toggle](../src/app/theme-toggle.tsx), [icon](../src/app/icon.svg), and [web manifest](../src/app/manifest.json) provide app-wide presentation and metadata. |
| `/dashboard` | [Dashboard page](../src/app/dashboard/page.tsx) reads warehouse-scoped counts and recent items from [dashboard stats](../src/server/dashboard/get-dashboard-stats.ts). [Actions](../src/app/dashboard/actions.ts) handle logout; [mobile navigation](../src/app/dashboard/mobile-nav.tsx) is the responsive client navigation. |
| `/items` and `/items/[id]` | [List page](../src/app/items/page.tsx) connects item, category, and location reads; [item actions](../src/app/items/actions.ts) adapt create, edit, archive, restore, and quantity forms. [Create modal](../src/app/items/item-create-modal.tsx) and [filters](../src/app/items/item-filters.tsx) are client UI. [Detail page](<../src/app/items/[id]/page.tsx>) composes item, category, and location data with [item actions](<../src/app/items/[id]/item-actions.tsx>), [quantity controls](<../src/app/items/[id]/quantity-actions.tsx>), and [barcode panel](<../src/app/items/[id]/barcode-panel.tsx>). |
| `/categories` and `/categories/[id]` | [List page](../src/app/categories/page.tsx), [server actions](../src/app/categories/actions.ts), and [create modal](../src/app/categories/category-create-modal.tsx) manage the selected warehouse's categories. [Detail page](<../src/app/categories/[id]/page.tsx>) and [detail actions](<../src/app/categories/[id]/category-actions.tsx>) handle an individual category. |
| `/locations`, `/locations/new`, `/locations/[id]` | [Location list](../src/app/locations/page.tsx) and [tree component](../src/app/locations/location-tree.tsx) present the hierarchy; the [create modal](../src/app/locations/location-create-modal.tsx) and [create action](../src/app/locations/new/actions.ts) add locations. [Detail page](<../src/app/locations/[id]/page.tsx>), [detail actions](<../src/app/locations/[id]/actions.ts>), and [client controls](<../src/app/locations/[id]/location-actions.tsx>) edit or remove locations. |
| `/scan` | [Scanner page](../src/app/scan/page.tsx) hosts the camera/manual barcode UI in [scanner](../src/app/scan/scanner.tsx). It looks up items through the barcode API and navigates to the item detail route. |
| `/warehouses` and `/settings/warehouses` | [Warehouse actions](../src/app/warehouses/actions.ts) adapt creation, deletion, and membership updates; [warehouse form](../src/app/warehouses/warehouse-form.tsx), [delete form](../src/app/warehouses/delete-warehouse-form.tsx), and [access manager](../src/app/warehouses/warehouse-access-management.tsx) provide UI. [Switch action](../src/app/warehouses/switch-actions.ts) validates access before setting the active warehouse. The [warehouse settings page](../src/app/settings/warehouses/page.tsx) loads the access-management view. |
| `/login` and registration | [Login page](../src/app/login/page.tsx), [login form](../src/app/login/login-form.tsx), and [login actions](../src/app/login/actions.ts) cover password login, two-factor verification, and passkey login completion. [Registration page](../src/app/users/new/page.tsx), [form](../src/app/users/new/register-form.tsx), and [action](../src/app/users/new/actions.ts) create accounts when registration is enabled. |
| Password workflows | `/change-password` uses its [page](../src/app/change-password/page.tsx), [form](../src/app/change-password/change-password-form.tsx), and [action](../src/app/change-password/actions.ts). `/forgot-password` uses [page](../src/app/forgot-password/page.tsx), [form](../src/app/forgot-password/forgot-password-form.tsx), [action adapter](../src/app/forgot-password/actions.ts), and [action core](../src/app/forgot-password/action-core.ts). `/reset-password` uses [page](../src/app/reset-password/page.tsx), [form](../src/app/reset-password/reset-password-form.tsx), and [action](../src/app/reset-password/actions.ts). |
| `/settings` | [Settings page](../src/app/settings/page.tsx) joins account and security data. [Account tabs](../src/app/settings/account-tabs.tsx), [profile/password forms](../src/app/settings/settings-forms.tsx), [email-change form](../src/app/settings/email-change-form.tsx), and [security UI](../src/app/settings/security-settings.tsx) are client-facing; [profile/password actions](../src/app/settings/actions.ts) and [security actions](../src/app/settings/security-actions.ts) perform mutations. |
| `/admin`, `/admin/email`, and `/admin/oidc` | [Admin page](../src/app/admin/page.tsx) is the global user/registration administration surface. [Admin actions](../src/app/admin/actions.ts) delegate user and registration changes; [tabs](../src/app/admin/admin-tabs.tsx), [user forms/actions](../src/app/admin/create-user-form.tsx), [role form](../src/app/admin/user-role-form.tsx), [user controls](../src/app/admin/user-actions.tsx), and [registration form](../src/app/admin/registration-settings-form.tsx) make up its UI. `/admin/email` has a [settings page](../src/app/admin/email/page.tsx), [server actions](../src/app/admin/email/actions.ts), [action core](../src/app/admin/email/action-core.ts), and [settings forms](../src/app/admin/email/settings-forms.tsx) for SMTP configuration and test mail. `/admin/oidc` has a [settings page](../src/app/admin/oidc/page.tsx), [server action](../src/app/admin/oidc/actions.ts), and [settings form](../src/app/admin/oidc/settings-form.tsx); shared validation, secret encryption, and provider revisions are handled by [OIDC settings](../src/server/settings/oidc.ts). See the [OIDC guide](oidc.md) for provider setup and operational constraints. |
| HTTP API | [Auth route](<../src/app/api/auth/[...all]/route.ts>) adapts Better Auth to Next.js. The [barcode lookup route](../src/app/api/items/by-barcode/route.ts) resolves an item in the active warehouse; [barcode image route](<../src/app/api/items/[id]/barcode/route.ts>) returns SVG or PNG for an accessible item. |

## Shared UI: `src/components`

- [App header](../src/components/app-header.tsx) and [user menu](../src/components/user-menu.tsx) form shared navigation; [warehouse switcher](../src/components/warehouse-switcher.tsx) uses the warehouse switch action.
- [Button](../src/components/button.tsx) and [modal](../src/components/modal.tsx) are reusable UI primitives.
- [Install prompt](../src/components/install-prompt.tsx) supports the installable app experience.

## Runtime and integration helpers: `src/lib`

- [Auth server configuration](../src/lib/auth.ts) configures Better Auth and its Prisma integration; [OIDC provider configuration](../src/lib/oidc-provider-config.ts) builds the dynamic generic OAuth provider; [auth client](../src/lib/auth-client.ts) exposes browser-side auth helpers.
- [Prisma client](../src/lib/db/prisma.ts) initializes PostgreSQL access. The source schema lives at [prisma/schema.prisma](../prisma/schema.prisma).
- [Passkey configuration](../src/lib/passkey-config.ts) supplies passkey settings; [local return path](../src/lib/local-return-path.ts) constrains post-login navigation.

## Server domain: `src/server`

Server modules own reusable business logic and database access. Route components and Server Actions should call these modules rather than duplicate domain rules.

| Area | Responsibility and key relationships |
| --- | --- |
| `auth` | [Current-session helpers](../src/server/auth/get-current-user.ts) provide active-user identity and session data; [permissions](../src/server/auth/permissions.ts) enforce the global role. [Password reset](../src/server/auth/password-reset.ts) and [token helpers](../src/server/auth/password-reset-tokens.ts) implement reset flow, while [session deletion](../src/server/auth/delete-session.ts) supports logout and [two-factor policy](../src/server/auth/two-factor-policy.ts) centralizes MFA state rules. |
| `warehouses` | [Current warehouse](../src/server/warehouses/current-warehouse.ts) resolves the cookie selection against user access. [Permission/transaction wrappers](../src/server/warehouses/permissions.ts) scope reads and writes; [transaction locks and access checks](../src/server/warehouses/transaction-lock.ts) protect access boundaries. [Management](../src/server/warehouses/manage-warehouses.ts) handles warehouses and memberships, with [isolation checks](../src/server/warehouses/check-isolation.ts) guarding destructive operations. |
| `items` | [Create](../src/server/items/create-item.ts), [update](../src/server/items/update-item.ts), [quantity change](../src/server/items/change-item-quantity.ts), [archive](../src/server/items/delete-item.ts), and [restore](../src/server/items/restore-item.ts) enforce item rules and write history. [List](../src/server/items/list-items.ts), [get](../src/server/items/get-item.ts), and [history](../src/server/items/list-item-history.ts) provide scoped reads; [barcode generation](../src/server/items/generate-barcode.ts) supports creation. |
| `locations` and `categories` | Each has create, update, delete, get, and list modules. Location operations preserve the parent hierarchy and item constraints ([location create](../src/server/locations/create-location.ts), [location list](../src/server/locations/list-locations.ts)); category operations remain attached to the active warehouse ([category create](../src/server/categories/create-category.ts), [category list](../src/server/categories/list-categories.ts)). |
| `users` | User administration and account changes are split into focused operations: [create](../src/server/users/create-user.ts), [list](../src/server/users/list-users.ts), [delete](../src/server/users/delete-user.ts), [global role update](../src/server/users/update-user-role.ts), [status](../src/server/users/set-user-status.ts), [password reset](../src/server/users/reset-user-password.ts), [password-change requirement](../src/server/users/set-password-change-required.ts), [MFA reset](../src/server/users/reset-user-two-factor.ts), [profile update](../src/server/users/update-profile.ts), and [password change](../src/server/users/change-password.ts). |
| `settings` and `security` | [Registration settings](../src/server/settings/registration.ts), [email/SMTP settings](../src/server/settings/email.ts), and [OIDC settings](../src/server/settings/oidc.ts) back admin settings screens. The [APP secret encryption helper](../src/server/security/secret-encryption.ts) encrypts SMTP and OIDC settings. [Email rate limits](../src/server/settings/email-rate-limit.ts) are shared by test mail and reset flows; [security settings read](../src/server/security/get-security-settings.ts) supplies the account security UI. |
| `email` and `dashboard` | [Mail delivery](../src/server/email/send-mail.ts) is shared by verification, reset, and admin test flows; [verification email](../src/server/email/email-verification-mail.ts) formats that message. [Dashboard stats](../src/server/dashboard/get-dashboard-stats.ts) aggregates active-warehouse inventory data. |

## Generated output and assets

`src/generated/prisma` contains generated Prisma client modules and should not be hand-edited. [The maintained Prisma schema](../prisma/schema.prisma) defines the database models and enums. App-owned static resources include [the SVG icon](../src/app/icon.svg), [web manifest](../src/app/manifest.json), and [Apple touch icon](../src/apple-touch-icon.png).
